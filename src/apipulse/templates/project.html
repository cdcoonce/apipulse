About apipulse

apipulse is a live-probe quality index for public APIs. Once a day it checks one representative endpoint of each listed API and publishes reachability, latency, auth and rate-limit signals, so you can see which public APIs actually work today.

What a probe sends

  • Method: GET.
  • Frequency: one request per API per day.
  • User-Agent: {{ user_agent }}
  • Credentials: none. A probe is sent with no credentials, meaning no API keys, cookies or Authorization headers.
  • Body: none. The request has no body.

How to opt out

If you run one of these APIs and do not want it probed, open an issue at https://github.com/cdcoonce/apipulse/issues titled opt-out: <host>, where <host> is the host name to exclude. The maintainer adds the host to data/optout.json; the API stops being probed and is listed on the removed page so its absence is not read as death.

JSON API

  • /v1/apis?q= searches the index by name, description and tags and returns summaries ranked by relevance, then reachability, working days and median latency.
  • /v1/apis/{id} returns everything known about one API, including its 30-day history, auth and rate-limit signals.

Every API also has a badge at badge/<id>.svg and a machine-readable list in apis.json.

What the labels mean

  • Endpoint probe. The probe called a real endpoint taken from the API's OpenAPI spec, so its status says whether the API itself answered.
  • Site probe. No endpoint was known, so the probe called the API's website instead. That shows the site is up, not that the API works.
  • Auth is measured only at endpoints. No key, Key required and Unclear appear only for an endpoint probe. Listed means what the public-apis list or APIs.guru declares about auth; apipulse did not measure it.
  • Worked means the API answered with an HTTP 2xx status. Answered means it sent any HTTP response, even an error.
